# 还有哪些问题（包方案继续执行下去的全部缺口）

> 按严重程度排序。每项写清影响与建议方案。标“需用户批”的，没有批复不要擅自做。

## 1. PostgreSQL 与现 SQLite 的取舍与迁移成本

- **现状**：包是 PostgreSQL（`sql/schema.sql`，含 `distinct on`、jsonb、`on conflict`、
数组聚合等 PG 专属写法）；现站是 mini 上的 SQLite（`app/models.py`，SQLAlchemy 模型）。
- **影响**：包的 `db.py`、`compute/jobs.py`、`publish/service.py`、`api/repo.py`、
`flows/run.py` 里的 SQL 不能直接跑在 SQLite 上；`theme_heat_ts`、`relevance_scores`、
`facts`、`content_versions`、`users/subscriptions/orders` 这些表现站都没有。
- **建议方案**：
- A（推荐，第 2 步）：mini 上装 PostgreSQL（standalone 安装包，不用 docker，
mini 是 macOS，可用 Postgres.app 或官方 pkg 安装），新库按 `schema.sql` 建表，
写一次性迁移脚本把现站 SQLite 数据（题材 21 个、公司 105 家、分层、人形机器人
与 TOPCon 内容、报告）导过去，核对行数后再切 `DATABASE_URL`，旧库保留只读备查。
- B（不迁）：把包的 SQL 逐条改写成 SQLite 方言。工作量不比迁移小，且以后每次
包更新都要再改写一遍，不推荐。
- **待定**：选 A 还是 B；A 的话由谁在 mini 上装 PG（需要用户在 mini 上操作或授权）。

## 2. Tushare `daily` 接口无权限

- **现状**：token 有效，但账号无 `daily` 接口权限（2026-11-08 mini 实测）；
`daily_basic`（5573 行）、`stock_basic`、`trade_cal` 均可用。
- **影响**：包的 `TushareDaily`（`daily` + `daily_basic` 合并）跑不起来，
`quotes_daily` 任务（收盘日线 → 公司页行情与市值 → 关联度重算）整条断。
- **建议方案**：
- A（推荐）：改采集器为 `daily_basic`（close、total_mv、pe_ttm 等）+ AKShare
补 OHLC/成交额/涨跌幅（东财接口已实测可用），`pct_chg` 由连续收盘价推导；
改动小，且不依赖账号积分。
- B：给 Tushare 账号赚积分开 `daily` 权限（按 Tushare 积分规则，捐赠/分享可得积分；
具体要多少分开 `daily`，以 Tushare 权限页为准，不要猜）。
- **待定**：选 A 还是 B。

## 6. 内容抽取：模型已定为 Muse，评测集与方法已写成文档（评测待跑）

- **已定（2026-11-08 用户定）**：抽取模型不再是 Anthropic Claude，改成 **Muse
  （即本助手）**。包 `extract/pipeline.py` 与 `revenue_extractor.py` 原先写死
  `anthropic.Anthropic()` + 默认模型 `claude-sonnet-5-5`，已改成可配置/可插拔：
  `config/llm.yaml`（provider 默认 `muse`）+ `backend/app/extract/llm_client.py`
  （注册表：muse / manual / anthropic，Anthropic 只作为其中一种可选实现，
  模型与 key 都走配置，代码里不再写死模型名）。
- **执行方式**：Muse 没有给后端代码直接调的 API key，后端只生成抽取任务
  （`MuseClient.extraction_job()`：提示词 + 文档 + 校验规则），抽取由助手在
  定时或手动流程里执行。**不编造假的 Muse API 端点或 key；不跳过校验直接入库。**
  无论谁抽取，输出都必须过校验器（引文真实存在于原文、数字/年份/日期与引文
  一致、无评价性措辞），再过发布闸门才能入库。
- **评测（前置条件，未变）**：上任何模型之前，先在 **30 份以上真实文档**上评测
  提示词，结果交用户批准后才能上线。评测集与评测方法已写成正式文档
  `docs/EXTRACTION_EVAL.md`：30 份构成（年报分产品收入 15 + 公告/研报事实陈述
  10 + 政策文件 5，覆盖人形机器人/TOPCon电池/绿色电力）、gold 标注方法、
  冻结清单格式（`docs/eval_set/manifest.json`，含 source_url/sha256/版本）、
  计分口径（漏抽率/误抽数/校验拦截率/漏网数/收入份额误差，代码在
  `backend/app/extract/eval_scorer.py`）、跑分脚本 `scripts/eval_extraction.py`、
  通过门槛（漏网必须为 0 是硬门槛；漏抽率 ≤ 20%、收入份额最大绝对误差 ≤ 0.01
  是建议值，需用户批准）。
- **待做**：冻结评测集清单（逐份取真实文档 + 标 gold）、跑评测、报告交用户批准。
  在此之前抽取管线保持关闭，概况/时间线继续人工写（现站人形机器人那套已核验
  内容不受影响）；`theme_facts` 任务（每 30 分钟）不能开。
- **待定**：评测门槛的两个建议值用户是否批准；评测的 30 份文档清单用户是否过目。

## 7. 实时行情没有持牌生产适配器

包里没有实现。现站走东财/AKShare（公开接口，未签授权）。
- **影响**：DEPLOY.md 明确写着“实时行情和再分发需持牌数据商授权”；严格说，
现站的实时榜单与包的 demo 模式都处在“先跑起来、授权待补”的状态。
- **建议方案**：短期继续用东财/AKShare（已实测可用），并在方法说明页与页脚如实写清
数据来源；长期（流量起来后）评估持牌数据商授权或改用 Tushare（已有 token，
但实时行情仍需确认授权范围）。合规确认（律师看产品形态与页面措辞）列入上线清单，
不是代码能解决的。

## 8. ICP 备案：现在不用，将来可能要

- **现状**：站不在大陆服务器上（Cloudflare + 用户家 mini），不用办 ICP。
- **影响**：如果将来把后端或前端迁到大陆服务器（阿里云/腾讯云）或接大陆支付，
就必须办 ICP 备案（经营性网站还要办 ICP 证）。
- **建议方案**：保持现有部署不动，就不用办；爱发电方案也不需要本站办 ICP
（收款在爱发电那边）。迁服务器之前先把备案排进计划。

## 9. HTTPS 强制跳转是 Cloudflare 侧设置

- **现状**：`http://tcs.999777888.xyz` 目前直接返回 200，不跳 https。
- **影响**：SEO 与安全扣分；包的 DEPLOY 清单也要求开启 HTTPS。
- **建议方案**：用户在 Cloudflare Dashboard（999777888.xyz 域名）开
“Always Use HTTPS”（SSL/TLS → Edge Certificates → Always Use HTTPS），
1 分钟生效，无需改代码。开完后验证 `curl http://tcs.999777888.xyz` 返回 301。

## 12. 交易日历每年要导入

- **现状**：包靠 `trade_cal` 表过滤节假日，需每年导入；现站 `is_trading_time`
只认周六日，法定节假日会误判为交易日（例如春节连休期间仍会尝试刷新，
失败后走 stale 路径，不会编数据，但会多几次无用拉取）。
- **建议方案**：第 2 步迁移时把 Tushare `trade_cal`（已验证可用）接进来，
每年年初导入一次；第 1 步先在方法说明页写清“节假日口径以交易所公告为准”。

## 14. 告警 webhook 未配置

- **现状**：包的新鲜度巡检支持 `ALERT_WEBHOOK_URL`（失败时发告警）；现站没有

由用户定），配进 mini 后端 `.env`；在那之前，巡检只写日志。
